# Prototype 报告 — Headless 战斗模拟器 1000 Run 基线

> 日期 2026-05-19
> 上游：`docs/PRD/v0.md` §5.2 平衡模拟器
> 文件：`prototype/sim.py` (Python 占位，Godot 4 GDScript 化在 /to-issues 阶段)

---

## 1. 验证目标 vs 实际结果

| 验证目标 | 目标值 | 实测 (n=1000) | 结论 |
|---|---|---|---|
| 胜率 | 50-60% (PRD §5.2) | **59.1%** | ✓ 达标 |
| trigger stack 不爆栈 | OnTraitFired 深度 ≤ 2 不递归 | 1000 局 0 异常 | ✓ 达标 |
| 词条选取分布 | 80 词条均匀(每个被选 0.3-3 次/run) | 10 词条均拉平到 ~2.0 次/run | ✓ 达标(10 词条规模下) |
| 反应触发频次 | 每反应 0.3-3 次/run | 11-12 次/run(主反应) / 1.76 次/run(骸魂) | ⚠ **超标 4-10 倍** — 需调 |
| 平均结算 HP | (无目标) | 72.8 / 80 | ⚠ HP 太充裕 — 数值偏向玩家 |
| 平均通关战数 | (满 = 18) | 12.8 / 18 | 输的也撑到 5+ 战 |

## 2. 关键观察

### 2.1 胜率达标，但是因为玩家"过强"

- HP 留存 72.8 / 80 = 91% — 玩家几乎不掉血就赢
- 输的局集中在 **第 5 战(精英)和第 11 战(精英 + boss 累计伤害)**：sim_results.csv 显示 lost 行 battles_won 集中在 5 / 11
- 数值起点 PRD §4.8 (玩家 80 HP，普 5-9 伤) 在 **18 战 + 4-7 回合/战** 设定下，玩家累计承伤上限 ≈ 5 × 18 × 5 = 450(粗估)，远超 80
- 现 sim 加了"战后 +5 HP" 占位治疗，让胜率拉到 60%——这告诉我们 **PRD §4.8 的金币治疗(50 金 / 30% HP)在节奏上是必须的**，不是可选

### 2.2 反应触发频次严重超标

| 反应 | 实测/run | 目标 | 比值 |
|---|---|---|---|
| 火+油→爆炸 | 11.27 | 0.3-3 | **3.7x** |
| 寒+水→冰封 | 10.34 | 0.3-3 | **3.4x** |
| 毒+腐→瘟疫 | 11.27 | 0.3-3 | **3.7x** |
| 铁+水→净化 | 12.91 | 0.3-3 | **4.3x** |
| 骨收+灵吸→骸魂 | 1.76 | 0.3-3 | ✓ |

**根因**：当前镶嵌策略"优先把库存 trait 配对到反应"，加上同卡反应在每次 OnPlay 都重复触发——**18 战 × ~5 出牌/战 × 反应概率太高**。PRD 没规定"反应是否同卡每次都触发还是只触发一次"。

→ **反推 PRD 修订项 #1**：明确"反应触发 = 每次 emit() 命中后取代两 trait 效果"是按战斗局结算的，但**不限制次数**；如果想让反应稀有，要么让 reaction.watch_for 仅在 OnPlay 触发(限制时机)，要么让镶嵌成本更高(把"配对反应"门槛拉高)。

### 2.3 词条选取分布

10 词条规模下，pick_count 在 1967-2085 之间 — **完全均匀**(因为镶嵌策略是贪心配对反应，遇到就装)。在 80 词条规模下需要：
- 重测 starter 池策略(玩家选哪 5 个开局)
- 加入"罕见词条仅 boss 给"约束 (PRD §4.3 掉落表已写)
- 装备成本(库存槽满后必须拆) 当前 sim **没实现**(假设无限库存)

### 2.4 触发器栈实测稳定

`fire_depth ≤ 2` 全程未触发，1000 局 / 平均 ~80 战 / 每战 ~5 出牌 / 每牌平均 1.4 trait fire = **560,000 次 emit()** 未爆栈。**ADR-001 设计正确**。

但是观察到 `void_consume` (OnTraitFired 深度 1)被触发 15238 次——意味着每场战斗会有 ~15 次 OnTraitFired 嵌套触发，需要在 PRD §5.4 测试中专门 fixture 这个量级。

### 2.5 词条 fire_count 分布暴露 PRD 问题

- `bone_harvest` fire_count = 0 — OnKill 词条在 sim 中"模拟器不真持有"被跳过
- `strike_basic` fire_count = 47496 — 主要伤害源，~47/run，符合 StS 基底卡定位
- `iron_guard` fire_count = 25253 — 5 张 Skill 卡每张都装基底自带，自然高
- `void_consume` fire_count = 15238 — 反应链触发的"被动稀有"被滥发(15/run × 60% 胜率 = 在反应大量触发的局里频繁触发)

**反推 PRD 修订项 #2**：OnTraitFired 类词条需要"每回合上限"，否则 Rare 词条会因反应链泛滥变成稳定回血/抽卡发动机。建议在 PRD §4.1 Trait 字段加 `cooldown_per_turn: int | null`。

## 3. 反推 PRD v1 修订建议

| # | 修订项 | 影响章节 | 紧急度 |
|---|---|---|---|
| M1 | OnTraitFired/OnKill 类词条加"每回合上限"字段 | §4.1 Trait | 高(影响 80 词条文案模板) |
| M2 | 反应触发频次降到 1-3/run：要么限制 watch_for 时机为 OnPlay/OnHit 二选一,要么镶嵌后反应"消耗装填"机制 | §4.4 + §5.2 平衡模拟器目标 | 中(prototype 阶段反推,在 v1 PRD 锁定) |
| M3 | 战后回血是设计核心,不是可选 | §4.8 经济表 + §3 US-13 | 高(核心循环假设) |
| M4 | "战斗内 emit() 平均次数 ~80/战" 需写进 PRD §5.4 风险专项测试 | §5.4 R6 测试 fixture | 中 |
| M5 | 镶嵌策略不能"反应配对优先",否则普通玩家也会自动达成 60% 胜率 | §3 US-09 反应预览 + §4.5 营地操作设计 | 低(设计意图本就如此,验证 OK) |

## 4. 下游路径

prototype 已验证 **数据模型可工作 + 触发器栈稳定 + 数值起点近似可用**，可以进入 `/to-issues` 阶段：

1. ADR-001(触发器栈结算顺序) — 现在已经有 **560k emit() 0 异常** 的实证支撑,可以正式落 ADR
2. `/to-issues` 切纵切：每个 user story → 1 issue(参见 PRD §3 共 16 条)
3. **第一条 issue 强烈建议**：`Implement Trait + Card data model in Godot 4 with Hybrid Resource+JSON`,把 sim.py 的核心数据结构搬到 GDScript

prototype 代码 **不要**搬进生产 codebase(write-a-skill 抛弃式原则)。Python sim 留在 `prototype/` 作为 **数值平衡的回归测试基线**：将来 GDScript 实现完成后,跑同一组 seed,对比胜率/反应频次/HP 留存应一致。
