## 1. Problem Statement

**核心用户问题**：StS 老玩家在通关无数次后，渴望"卡牌构筑"之外的新维度——他们已经背完了所有卡的固定文本，combo 路径只剩"哪 3 张能成立"的查表式记忆。Inscryption 的 sigil 拼装给出过答案，但被困在 12 小时的一次性叙事里，**没人把"sigil 化原子词条"做成可复玩的 roguelike**。

**目标受众**：r/slaythespire 与卡牌 roguelike Discord 的核心玩家——具体画像是已通关 StS A20+ 或 MT Cov15+ 的人，他们能识别"3 能量 / 抽 5 / 明牌意图"的 StS 基线，并且把每一处偏离视为创新成本。

**为何 StS / StS2 / Inscryption / MTG 不够**（见 A1, A2）：
- StS / StS2 的卡牌是**固定数据库**，构筑空间 = 选哪几张，玩家对每张卡只能"选或不选"，没有"塑形"的余地。
- Inscryption 的 sigil 不能拆装，且全流程 12-15 小时即耗尽（A3）。
- MTG 的 keyword 只读不写——玩家在游戏中无法"获取一个 keyword 焊到任意牌上"（A2 §2.2）。

**项目主张**：把"卡 = 基底 + 3 个可拆装词条"做成 30-40 分钟一局的 roguelike，**击杀敌人吞噬其词条，回营地用炼金台拼装**，让卡组在 run 内持续塑形。

---

## 2. Solution

一款 **30-40 分钟单局** 的卡牌 roguelike：玩家扮演**巫女**，每局选 1 种基底卡组（Attack / Skill / Rite，见 CONTEXT §2 Q9），战斗采用 StS 基线（3 能量 / 抽 5 / 手牌 10 / 明牌意图，见 A1 §3）。**击杀敌人后吞噬其词条**（普通敌 60% 给 1 / 30% 给 2 / 10% 给 0；精英 100% 给 2；boss 必给 3，见 A4 §3 Q2），回营地把词条**镶嵌到卡的 3 个槽位**或**拆下来收进库存**（CONTEXT §4 数据模型，A4 §3 Q5 价格表）。

**词条池约 80 个，按 6 学派 × 8 触发时机正交分布**（A2 §9，CONTEXT Q4），稀有度 50/22/8（A4 §3 Q3）。**特殊反应只做 20-30 个高光时刻**（火+油→爆炸式），其余靠"触发器栈"——同一事件被多个词条监听后自然冒泡（A2 §1.4，CONTEXT §4 战斗结算伪代码）。这把组合爆炸从 80×80=6400 降到 80+25 个测试面（CONTEXT §5 R1）。

**差异化叙事「吞噬式黑魔法」**：玩家不是英雄，而是**用敌人的尸体词条供养自身卡组的巫女**（A5 §1.1）。美术沿 **Cult of the Lamb** 风（高饱和血红+墨绿+骨白、扁平 vector + 粗黑 outline、Spine 2D），叠加 Wildfrost 的圆润卡面与图标系统（A5 §设计建议）。

**单局节奏**：4-7 回合 / 战，单局 12 战 + 3 精英 + 3 boss（A1 §3，A4 §1.6），单 run 词条流通量 25-30 个（CONTEXT §5 R3，A4 §3 Q1）。

**元进度路径**：Hades + Monster Train 混合，**首 10 局每局解锁内容**，速度是 StS 的 2-3 倍（A3 §3.1, §设计建议）。

## 3. User Stories

> 每条用户故事覆盖核心循环的关键决策点。`As a 巫女玩家, I want X, so that Y.`

### 战斗循环

**US-01**（出牌）
> As a 巫女玩家, I want 在战斗中查看每张手牌上的 3 个词条图标和组合后的实际效果文本（不是各词条独立堆叠的 raw 列表）, so that 我能在 3 能量约束下快速判断本回合的最优出牌顺序。
> 来源：A1 §3, A5 §ASCII Mockup 战斗界面

**US-02**（看意图）
> As a 巫女玩家, I want 看到敌人下回合的明牌意图（攻击数值 / 格挡 / buff / debuff，StS 风），并能看到敌人身上**携带的词条图标**（决定吞噬奖励）, so that 我能同时为"本回合活下来"与"为奖励选择该杀谁"做决策。
> 来源：A1 §2.1, CONTEXT §4 Enemy.carried_traits

**US-03**（触发反应）
> As a 巫女玩家, I want 在打出一张同时挂有"火"和"油"词条的卡时，系统自动结算特殊反应（爆炸：高额单体 + 范围溅射），并在结算时高亮该反应的卡面 + 触发音效, so that 我能感受到"我配出来的"反应被游戏认可，而不是只看见冰冷的伤害数字。
> 来源：A2 §9 反应表设计，CONTEXT §4 SpecialReaction

**US-04**（看反应预览）
> As a 巫女玩家, I want 在悬停一张手牌时看到所有会触发的词条+反应栈（按 slot 0→1→2 顺序展开），并预览每一步对敌人的伤害/状态预估, so that 我能在结算复杂连锁前心中有数。
> 来源：A2 §1.4 链式触发，CONTEXT §6 R6

**US-05**（击杀掉词条）
> As a 巫女玩家, I want 在击杀敌人时看到"吞噬"动画（敌人化为黑烟被吸入巫女）并立即弹出其携带词条的获取提示, so that 我感受到"杀敌 = 资源积累"的因果直觉，而不是把词条当成中性的金币奖励。
> 来源：A5 §设计建议（吞噬色彩心理），A2 §1.6（吞噬即获得）

### 营地拼装

**US-06**（拆装）
> As a 巫女玩家, I want 进入营地后看到我的 15-20 张卡，每张卡的 3 个槽位是否填满一目了然（slot[0] 必为基底自带且锁定）, so that 我能直观地找到"哪张卡还有 build 空间"。
> 来源：CONTEXT §4 Slot.locked, A4 §3 Q1（30-40 可填槽）

**US-07**（拖拽镶嵌）
> As a 巫女玩家, I want 把库存中的词条**拖拽**到目标卡的空槽上（拖到非槽位区会回弹），松开瞬间听到 "哒" 的吸附音效, so that 我用 5 秒就能学会装配，且物理隐喻让操作不易出错。
> 来源：A5 §范式 A 拖拽到卡槽

**US-08**（拆卸入库存）
> As a 巫女玩家, I want 在营地花费 50 金币 + 1 拆卸点把已镶嵌的词条**拆下来收进库存**而不是销毁, so that 我可以在新的稀有词条出现时把旧词条搬到更合适的卡上，不被早期决策永久绑死。
> 来源：CONTEXT Q8 v1（可拆卸入库存），A4 §3 Q5

**US-09**（反应预览 diff — **核心 UX**）
> As a 巫女玩家, I want 在拖拽词条到槽位时看到一个浮动 tooltip：删除线显示旧效果 + 绿色显示新效果，并标出会**新增/失效的反应**（含触发频次预估"每战 ~X 次"）, so that 我能预判这次替换是赚还是亏，且需要主动思考"配对反应"而不是被自动配对算法替代。
> 来源：A5 §3 反应预览信息密度，A5 §ASCII Mockup 营地，**M5 prototype 反推**（PROTOTYPE_REPORT §2.5：自动反应配对策略让所有玩家都达成 60% 胜率，本作设计意图是让"配对决策"成为玩家的策略空间，预览 = 让玩家做决策的核心工具）

**US-10**（补卡 / 补词条）
> As a 巫女玩家, I want 在路径上的商店里独立看到"卡商品"和"词条商品"两栏（金币 50/80/140 三档卡 + 40/70/120 三档词条）, so that 我能为"广度（多张卡）"或"深度（更强词条）"分别下注。
> 来源：A4 §3 Q5 价格表

**US-14**（巫女背景叙事钩子）

## 4. Implementation Decisions

> 把 CONTEXT v1 的关键技术选型 + 6 份研究里的具体数值锁死。

### 4.1 数据模型

**结构定义参见 CONTEXT §4**（不重复）。本节列具体 Trait 字段示例：

| Trait id | trigger | effect | value | school | rarity | cooldown_per_turn | flavor |
|---|---|---|---|---|---|---|---|
| `flame_brand` | `OnPlay` | `Damage(N, Fire)` | 4 | Fire | Common | `null` | "灼焰烙印：每次出牌额外造成 4 火焰伤害。" |
| `oil_slick` | `OnHit` | `Apply(Oil)` | 1 | Fire | Common | `null` | "渗油：本卡命中给目标加 1 层油。" |
| `bone_harvest` | `OnKill` | `Spawn(BoneToken)` | 1 | Bone | Uncommon | `1` | "骨收：每次击杀后下次抽牌堆顶生成 1 张骨牌（当回合上限 1 次）。" |
| `lunar_echo` | `EndTurn` | `Draw(N)` | 1 | Moon | Uncommon | `null` | "月之回响：回合结束抽 1。" |
| `void_consume` | `OnTraitFired` | `HealSelfPercent(N)` | 5 | Void | Rare | `1` | "虚空吞噬：本卡每次词条触发回血 5%（当回合上限 1 次）。" |

> **`cooldown_per_turn` 字段（M1，prototype 反推）**：
> - 类型：`int | null`。`null` = 无每回合上限；正整数 N = 该词条每回合最多触发 N 次（按 `card.id + trait.id` 计数）。
> - **强制要求**：`trigger ∈ {OnTraitFired, OnKill}` 的词条**必须**设 `cooldown_per_turn ≥ 1`，否则反应链触发会让 Rare 词条变成稳定回血/抽卡发动机（prototype 实测 `void_consume` 单 run 触发 15238 次，详见 `prototype/PROTOTYPE_REPORT.md` §2.5）。
> - 其他 trigger 默认 `null`，单独设上限属于设计决策（如平衡某个超模 OnPlay 词条）。

> 三轴正交分类（A2 §9 / CONTEXT §4 Trait.axis）使用：
> - **timing** = `TriggerEvent`（8 类：OnPlay / OnDraw / OnDiscard / OnKill / OnHit / StartTurn / EndTurn / OnTraitFired）
> - **scope** = Self | Card | Hand | Battlefield（4 类）
> - **school** = Fire | Decay | Moon | Iron | Bone | Void（6 类）
> 池规模 80 应覆盖 8×4×6 = 192 格的约 40% — 保留稀疏度作为 v1 后扩展空间。

### 4.2 战斗循环

锁定 StS 基线（**A1 §3 设计建议**，与 CONTEXT Q2 一致）：

| 项目 | 数值 | 来源 |
|---|---|---|
| 每回合能量 | 3，回合开始重置 | A1 §1, CONTEXT Q2 |
| 每回合抽牌 | 5 | A1 §1 |
| 手牌上限 | 10（结束自动弃） | A1 §1 |
| 词条槽 / 卡 | 3（slot[0] 锁定 = 基底自带） | CONTEXT §4 Slot |
| 弃牌堆 | 抽空自动洗弃为抽 | A1 §1 |
| 敌人意图 | 明牌（图标 + 数值） | A1 §1, CONTEXT Q2 |
| 战斗回合数 | 4-7 / 普通战，10+ / boss | A1 §3 |
| 关键字数量 | 控制在 20-25 个核心 keyword | A1 §3 |

**结算顺序锁定（CONTEXT §6 R6 → ADR-001）**：
- 同事件多词条结算：按 slot index 0 → 1 → 2 顺序。
- `OnTraitFired` 串联深度上限 = 2（防止递归无穷循环）。
- 特殊反应在 `emit()` 时插队，匹配后取代两个原效果并跳过下游（CONTEXT §4 战斗结算伪代码）。

### 4.3 词条池规模与稀有度

引用 A4 §3 Q3 + CONTEXT §2 Q4：

| 项目 | 数值 |
|---|---|
| 词条池总规模 | **~80** |
| 稀有度分布 | **50 普 / 22 稀 / 8 罕** |
| 学派 × 时机分布 | **6 学派 × 8 时机** 三轴正交（A2 §9.1） |
| 特殊反应数量 | **20-30 个**（A2 §1.4，CONTEXT §2 Q6） |
| 反应类型比例 | 70% 同时机反应 / 20% 跨学派反应 / 10% 反向抑制反应（A2 §9.2） |
| 同卡同词条堆叠 | **禁止**（A2 §9.3，规则 1） |
| 三件套反应 | **不做**（80³ 不可记忆，A2 §9.2） |

**敌人词条携带数（A4 §3 Q2，CONTEXT §4 Enemy）**：
- 普通敌：60% 给 1 / 30% 给 2 / 10% 给 0
- 精英：固定 2（其中至少 1 稀有以上）
- Boss：固定 3（含 1 罕 + 1 主题词条）
- 单 run 期望进账 ≈ **33 词条**（含拆装损耗后净持 25-30）

**掉落稀有度概率**：
| 敌人类型 | 普 | 稀 | 罕 |
|---|---|---|---|
| 普通 | 75% | 22% | 3% |
| 精英 | 40% | 50% | 10% |
| Boss | 0% | 40% | 60% |

### 4.4 反应表（示例 5 个）

引用 A2 §9.2 + CONTEXT §4 SpecialReaction 结构：

| watch_for | 触发时机 | 触发条件 | override_effect | flavor |
|---|---|---|---|---|
| `[flame_brand, oil_slick]` | `OnPlay` | 同卡同时存在 | `Damage(12, Fire) + AOE_Splash(4)` | "火 + 油 → 爆炸" |
| `[frost_bite, water_drop]` | `OnPlay` | 同卡同时存在 | `Apply(Frozen, 2 turns) + skip enemy intent` | "寒 + 水 → 冰封" |
| `[venom_touch, decay_spore]` | `OnHit` | 同卡同时存在 | `Apply(Plague, stacks=4)` | "毒 + 腐 → 瘟疫" |
| `[purify_light, venom_touch]` | `OnPlay` | 同卡同时存在 | `Cancel(both effects) + heal(3)` | "净化抵消毒（反向反应）" |
| `[bone_harvest, soul_drain]` | `OnKill` | 同卡同时存在 | `Spawn(SoulBoneCard) + DrawTopOfDeck` | "骨收 + 灵吸 → 骸魂卡" |

> **触发时机字段（M2，prototype 反推）**：
> - 每条反应**必须**绑定一个具体的 `TriggerEvent`（默认 `OnPlay`），而非"任意 emit() 命中即触发"。这避免 prototype 实测的"4 反应 / run 各触发 10-13 次"超标 4-10 倍现象（详见 `prototype/PROTOTYPE_REPORT.md` §2.2）。
> - **结算规则**：emit(event, card) 时只检查 `reaction.timing == event` 的反应，命中后取代两 trait 效果并跳过下游。
> - 反应触发频次目标：每反应 **0.3-3 次 / run**（5.2 平衡模拟器目标），平均每反应 ~0.5 次 / battle。
> - 同卡同 watch_for 反应**每回合最多触发 1 次**（与 §4.1 `cooldown_per_turn` 同机制，按反应 id 计数）。

> 完整 20-30 个反应表在 prototype 阶段填充，由 `data/reactions.json` 驱动（见 4.7）。

### 4.5 营地与库存

引用 CONTEXT §2 Q7 + Q8 v1：

| 项目 | 数值 / 规则 |
|---|---|
| 拼装位置 | **仅营地**（战斗内不可改） |
| 营地操作 UI | 拖拽到卡槽（A5 §范式 A） |
| 库存初始容量 | **5 槽** |
| 库存扩容 | 首个 boss 击败后 +5（共 10），第二 boss 后 +5（共 15），第三 boss 后 +5（共 20）（CONTEXT §5 R3） |
| 镶嵌空槽 | 免费（鼓励试错，A4 §3 Q5） |
| 替换覆盖 | 30 金币 |
| 拆卸入库存 | 50 金币 + 1 拆卸点（每幕 1 拆卸点 = 3 / run，事件 / 商店可补 2-3 个，预算见 4.8） |
| 重铸基底槽 | 100 金币 + 1 罕道具，单卡 1 次 |
| slot[0] | 基底自带，永远 locked，仅"重铸基底"可改 |

**初始卡组规模**：15-20 张（CONTEXT Q10），其中：
- 基底分布：~10 Attack + ~5 Skill + ~3 Rite（具体配比由初始卡组配置决定）
- 词条调度量：15-20 × 3 - 15-20（基底自带）= **30-40 个可填槽**

**镶嵌 UX（M5 prototype 反推 — 核心 UX 而非便利功能）**：
> prototype 实测：贪心"配对反应"自动镶嵌策略让玩家躺平就能 60% 胜率（`PROTOTYPE_REPORT.md` §2.5）。本作设计意图是让"配对决策"成为玩家的核心策略空间。
- **绝不**实现"自动配对反应"按钮（即使作为 QoL 功能也不行）
- 反应预览（US-09）= 营地核心 UX，需在拖拽时实时显示：
  1. 旧效果 / 新效果 diff
  2. 新增 / 失效的反应清单（含 watch_for + 触发时机）
  3. 触发频次预估（"~每战 X 次" 基于 4.4 的 0.3-3 / run 目标）
- 拖拽落点的吸附音效 + 动画反馈优先于"提示词信息密度"

### 4.8 数值起点

引用 A4 §1.6 表（与 StS 同量级、轻调过）：

**战后回血（核心循环假设，M3 prototype 反推）**：

> prototype 1000-run 实测：玩家 80 HP / 18 战 / 普通敌 5-9 伤 / boss 15-25 伤 → 累计承伤上限 ~450（远超 80）。**没有战后回血的话胜率会塌到 0%**。这不是可选的便利功能，是核心循环必需。详见 `prototype/PROTOTYPE_REPORT.md` §2.1。

| 时机 | 回血量 | 备注 |
|---|---|---|
| 每场普通战胜后 | **+5 HP**（自动，免费） | 核心保底，让玩家打满 18 场不饿死 |
| 每场精英战胜后 | **+10 HP**（自动，免费） | 精英伤害更大，回血也加倍 |
| 营地节点（每幕 1 次） | +30% maxHP（免费） | 强制治疗节点（路径上节点类型） |
| 商店治疗（可选） | +30% maxHP / 50 金 | 战略储备型（追求 boss 满血出击） |
| Boss 战胜后 | **+20 HP**（自动） | 衔接下幕的 buffer |

→ **战后回血总进账 / run ≈ 12 × 5 + 3 × 10 + 3 × 20 + 3 × 24（30% maxHP 的营地） = 162 HP**，与累计承伤 ~450 配合可达成 50-60% 胜率。

**HP 表**：
| 单位 | HP |
|---|---|
| 玩家起手 | **80** |
| 普通怪 | **12-25** |
| 精英 | **40-60** |
| Boss | **100-180** |

**金币经济（A4 §3 Q6）**：
| 来源 | 单次金币 | 频次 | 小计 |
|---|---|---|---|
| 普通战 | 15（12-18 浮动） | 12 | 180 |
| 精英 | 35 | 3 | 105 |
| Boss | 80 | 3 | 240 |
| 事件 | 30 平均 | ~5 | 150 |
| **总进账 / run** | | | **~675 金** |

**支出表（同 4.5 与 A4 §3 Q5）**：
- 商店买卡：50 / 80 / 140（普 / 稀 / 罕）
- 商店买词条：40 / 70 / 120
- 移除卡：75 起，每次 +25
- 拆词条：50 + 1 拆卸点
- 治疗（30% HP）：50
- 重铸基底：100 + 1 罕道具

**核心比率**：
- 商店购买力 ≈ 9-10 次决策 / run（StS 的 8-12 区间内）
- 移除使用率：理想 2-3 次 / run
- 词条净持 ≈ 25-30，覆盖 ~80% 槽位

**拆卸点预算（拆卸 = 词条复用经济的关键资源）**：
| 来源 | 数量 |
|---|---|
| 每幕通关必给 | 3（共 3 幕） |
| 事件节点平均 | 1.5（5 事件 × 30% 给拆卸点） |
| 商店购买（80 金 / 个，幕 2 起出现） | 1-2 |
| **单 run 总拆卸点** | **5-7** |

→ 玩家平均拆 5-7 次 / run，相当于"动 1/4 的镶嵌词条"，足够支撑 build 转向但不至于"无成本随便重铸"。

**单局节奏**：
- 总场次：12 普通 + 3 精英 + 3 boss = **18 战 / run**
- 总时长：30-40 分钟（CONTEXT §2 Q11）
- 单战长度：4-7 回合（普通战），10+（boss）

## 5. Testing Decisions

### 5.1 单元测试 — GdUnit4

覆盖最小需测试面：
- **Trait 触发**：每个 80 词条单独测 `OnX → Effect(value)` 在玩家 / 敌人状态上的副作用。
- **Reaction 命中**：每个 20-30 反应测 `watch_for` 命中 → `override_effect` 替代原效果 + 不再触发下游。
- **战斗结算**：固定 seed + 固定 deck + 固定敌人意图 → 期望确定的 HP / buff 结尾状态。
- **拼装规则**：slot[0] locked、同 trait 不可同卡重复（A2 §9.3 规则 1）、库存满时拆卸阻塞。
- **元进度状态机**：胜场记录、解锁阈值触发、死亡保留进度边界。

### 5.2 平衡模拟器 — headless 10k run

```bash
godot --headless --display-driver headless --audio-driver Dummy -s sim.gd
```

**输出 CSV 指标**（A6 §Part 4 第 5 条）：
- **胜率**：目标区间 **50-60%**（A4 §4 调参方向）。
- **词条选取分布**：80 词条出现频次（识别"无人选"与"必选"的两端）。
- **反应触发频次**：20-30 反应每 run 平均触发数，目标每反应 0.3-3 次 / run。
- **金币花费分布**：诊断货币通胀（A4 §4 风险 2）。
- **平均战斗回合数**：诊断节奏漂移。

每次 PR 跑 1k run 作为快速回归；nightly 跑 10k run 作为基线。

### 5.3 E2E 回放测试

固定 seed → 同样的玩家操作脚本 → 同样的最终状态。任何代码改动若破坏回放，CI 红灯。
覆盖目标：从开局到第一 boss 的完整流程（约 5-8 战）。

### 5.4 风险专项测试（来自 CONTEXT §5）

- **R1（平衡测试面）**：触发器栈架构后测试面 = 80 trait + 25 reaction = 105 个独立 case，必须每个有断言（不再是 80×80=6400）。
- **R6（触发顺序边界）**：专项 fixture 覆盖：
  - 同事件 3 词条 slot 0→1→2 顺序结算（断言数值）
  - `OnTraitFired` 深度恰好 2 时正常结算
  - `OnTraitFired` 深度 3 时被阻断（不抛异常）
  - 特殊反应在 emit 时插队 → 跳过下游 trait
  - 特殊反应阻断后 OnTraitFired 不冒泡
- **R6+（emit() 量级测试，M4 prototype 反推）**：prototype 实测单 run 累计 emit() ≈ ~80/战 × 18 战 ≈ 1440 次，1000-run 累计 56 万次未爆栈。需新增 fixture：
  - **单战 emit() 量级**：固定 deck（5 张 × 3 trait 满槽）+ 5 出牌/回合 × 5 回合 → 期望 emit() 调用数 70-100，断言无递归异常 + trait fire 总数偏离期望 ≤ ±10%
  - **emit() 深度日志哈希**：每次 emit() 记录 `(card.id, trait.id, depth, event)`，回归测试时对关键 seed 的日志做哈希 diff（防 silent regression）
  - **`cooldown_per_turn` 边界**：装 `void_consume`(cooldown=1)的卡，单回合 5 次出牌 → 该 trait 应只 fire 1 次，断言 `state.trait_fire_log.count("void_consume") == 1`

### 5.5 美术风险（A5 §3）

视觉验证不在自动化覆盖范围，但需在 prototype 阶段做 PoC：
- 3 词条 × 5 手牌 = 15 图标同屏可读性（剪影测试）
- 拖拽 vs 出牌的场景隔离（营地禁出牌、战斗禁改装）
- Steam Deck 7 寸屏 tooltip 不盖手牌

## 6. Out of Scope (v0)

明确不做：

1. **多人 / 联机**：单机单人。StS 2 的 4P 协作不效仿。
2. **多语言**：先英文 + 简中，其他语言留给社区或后续版本。
3. **移动端**：先 PC（Steam）+ Steam Deck。手机 / 平板原生不做（虽然 Cult of the Lamb 风格 + 拖拽 UI 兼容性强）。
4. **3D 视觉**：营地不做 3D 注魔台（A5 §范式 B 评估 ★★★，工程量翻倍且手机不友好）。**保 2D 全程**，营地用 2D 伪 3D 手绘背景（A5 §设计建议 2）。
5. **DLC / 季票**：v0 单包出货。扩展池（80 → 120 词条）留给 1.x。
6. **编辑器 mod 支持**：v1 后再说。模板（Slay-The-Robot）虽然支持，但不作为 v0 卖点。
7. **80 词条以上的扩展池**：v0 锁定 80 + 25 反应。多了会破坏稀有度分布与测试可达性。
8. **StS 第 4 幕这种长流程**：单局 30-40 min 上限，**不做"心脏"式额外幕**。
9. **PvP / 异步对战**：与单机叙事 / Build 探索冲突，且 80 词条平衡难以扛住对抗压力。
10. **故事大于玩法的 Inscryption 路线**：A3 §3.3 已论证一次性叙事陷阱。本作叙事是钩子，不是主轴。
11. **Magicraft 式法杖顺序敏感**：A2 §3.6，3 槽顺序敏感会让组合空间炸到 51 万，**显式拒绝**。
12. **Stacklands 式预设配方表**：A2 §4.6，本作要 emergent，反应表只做 20-30 个高光时刻。
13. **Hades 2 级别美术**：A5 §1.4 评估 N/A 做不起。
14. **三件套反应**：A2 §9.2 + 4.3 节，80³ 不可记忆，**显式拒绝**。
15. **"完美卡带回下一局"式重 meta**：A4 §3 Q4，会破坏下次 run 的探索曲线。
